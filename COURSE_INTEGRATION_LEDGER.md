# RENSA v4 — Course Integration Ledger

This document records what was extracted from the user's redacted ShivWorks/ECQC/IFWA notes into v4 architecture, and what was deliberately not converted into autonomous training.

## Integrated as abstractions

### State axes

- distance;
- entanglement;
- orientation;
- mobility;
- hand availability;
- information state;
- objective.

### Objective hierarchy

- Avoid
- Stabilize
- Resolve

### Decision concepts

- timing/selection can fail even when a motor action is familiar;
- an available exit can be a successful terminal solution;
- apparent success does not guarantee the problem has ended;
- goal-oriented problem solving is more important than forcing one preferred technique;
- hand availability and mobility constrain which response families remain usable.

### Contact-management abstractions

- observation/hold;
- verbal boundary channel;
- space/movement management;
- continuation after a boundary is respected or violated.

These are encoded as cognitive Problem Cards, not as universal legal/tactical prescriptions.

## Preserved as provenance only

- ECQC
- IFWA
- MUC
- instructor/course-derived conceptual lineage
- existence of a separate tool-context skill domain

## Deliberately not imported as generated procedure

The detailed operational weapon material in the source notes is not reproduced in the State compiler, including procedures for access, draw, firing, retention, weapon manipulation, malfunction clearance, confined-space weapon use, live-fire engagement, or weapon-oriented vehicle/ground procedures.

v4 instead reserves an `INSTRUCTOR` representation class so prior professional training can be indexed without RENSA inventing or autonomously teaching those mechanics.

## Provenance policy

RENSA distinguishes:

- **COURSE-DERIVED SYNTHESIS** — abstracted from the user's notes;
- **RENSA ABSTRACTION** — a model we created for the app;
- **PERSONAL MEMORY** — a recollection requiring later confirmation;
- **INSTRUCTOR-ONLY REFERENCE** — sensitive or operational material retained only as provenance/context.

This separation should remain mandatory in future versions.
